# Integration tests against two server targets

**Date:** 2026-09-22
**Module:** `github.com/cinc-project/cinc-api/integration` (existing nested module)

## Goal

Run one set of end-to-end tests against two servers:

- **cinc-server-ng**, the in-memory Go server, on every CI job (fast, no
  infrastructure).
- **cinc-server-erlang**, the CINC Server Erlang stack (erchef), started on
  demand in AWS by a developer, to confirm the client matches the server that
  users actually run.

The unit tests (`internal/cinctest`) and cinc-server-ng can both pass while
a request format is wrong. This session found several bugs that way: `all_files`
sent under API v1, a cookbook manifest without `metadata`, `Clients.Create`
without `create_key`, and the org ACL route. The cinc-server-erlang run is
the check that settles such cases, and the shared suite makes any
difference between the two servers show up as a named gap, not by accident.

## Decisions

| Topic | Decision |
|---|---|
| Test sharing | One suite, two targets. Each test is written once. |
| Layout | One Go module (`integration/`) with packages `suite`, `cincserverng`, `cincservererlang`, plus `terraform/`. |
| Naming | The targets are always called "cinc-server-ng" and "cinc-server-erlang", never "real". |
| Who runs the erlang suite | A developer, locally, with their own AWS credentials. No GitHub workflow. |
| Network | Public Elastic IP; security group allows 443 from the caller's /32 only; no SSH. |
| TLS | Throwaway CA generated by Terraform; the client trusts only that CA. No `WithSkipTLSVerify`. |
| Admin key | Generated locally by Terraform; only the public key reaches the instance. |
| Server-wide scope | The test admin is a server-admin, so users and association requests are covered; org create/delete is tested if erchef allows a server-admin to do it. The pivotal key never leaves the instance. |
| Secrets | None committed. AWS credentials come from the environment/profile; generated keys live only in local, gitignored state and output files. |

## Layout

```
integration/
  go.mod                       existing module
  suite/                       shared tests and helpers
  cincserverng/                cinc-server-ng target (CI)
  cincservererlang/            cinc-server-erlang target (ad hoc)
  terraform/                   AWS stack for cinc-server-erlang
    .out/                      generated target.json and admin.pem (gitignored)
  run-cinc-server-erlang.sh    apply → test → destroy
  README.md
```

## Section 1: shared suite (`integration/suite`)

### Target

```go
type Target struct {
    Name   string                          // "cinc-server-ng" | "cinc-server-erlang"
    Client func(t *testing.T) *cinc.Client // admin client for the test org
    Org    string
    Gaps   map[string]string               // subtest name → reason, with an issue URL or observed behaviour
}

func Run(t *testing.T, tgt Target)
```

`Run` runs every test as a subtest named `<family>/<case>`. Before running a
subtest it checks `tgt.Gaps` and calls `t.Skip(reason)` when the name is
listed. A `Gaps` entry with an empty reason fails the run.

### Coverage

Each endpoint family gets one test that creates, reads, lists, updates and
deletes, then checks that a read after the delete returns 404.

- **Organization scope:** nodes; roles (including per-environment run lists);
  environments (including `_default` being read-only: 405 on update);
  data bags and items (plain, and encrypted v1/v2/v3 round-trips); clients
  (the key returned on create, `Reregister`); keys (user and client);
  groups; containers; ACLs for each object type that has one, plus the org's
  own ACL; sandboxes; cookbooks (upload → get → download byte-for-byte →
  delete); cookbook artifacts; policies and policy groups (`PushRevision` to
  two groups); required recipe; principals; search (full, partial, `All`
  and `SearchAll` paging).
- **Server scope (as server-admin):** users (create, update, filter by email,
  delete); association requests (invite → accept, invite → reject);
  organizations (create/delete where erchef allows it for a server-admin).
- **Read-only:** status, license, universe, `_stats`.

### Negative tests

Written once in the suite; the server is expected to reject each:

- a cookbook manifest with no `metadata`;
- a cookbook manifest with `all_files` sent under API v1;
- a key field (`create_key`/`public_key`) on a client PUT.

On cinc-server-ng these are gaps linked to cinc-project/cinc-server-ng#159
and #160.

### Isolation and timing

- Every object name is `t-<test>-<random>`; every created object has a
  `t.Cleanup` that deletes it. Tests call `t.Parallel()`.
- No test depends on another test or on data already on the server.
- `eventually(t, timeout, fn)` retries a check until it passes or times out
  (30 s for search). cinc-server-erlang indexes asynchronously; cinc-server-ng
  passes on the first attempt.

### Existing tests

The 8 tests in `integration/*_test.go` move into `suite` unchanged in
behaviour, together with their cookbook fixtures and helpers.

## Section 2: targets

### `integration/cincserverng` (CI)

- Starts one in-memory cinc-server-ng per package run (org `test`, auth on, so
  the server itself verifies every request signature),
  in `TestMain`, and stops it after closing idle client connections.
- Calls `suite.Run(t, target)`.
- `Gaps`: every entry names an upstream cinc-server-ng issue. Initial
  entries: the manifest-validation negative tests (#160), the keyless client
  create (#159), and the org's own ACL route (a new issue, filed when the
  test is added).

### `integration/cincservererlang` (ad hoc)

- Reads the target file from `CINC_SERVER_ERLANG_TARGET`, or by default
  `../terraform/.out/target.json`:

  ```json
  {
    "server_url": "https://203.0.113.10",
    "org": "cincapi",
    "admin": "cincapi-admin",
    "key_path": "/abs/path/integration/terraform/.out/admin.pem",
    "ca_cert_path": "/abs/path/integration/terraform/.out/ca.pem"
  }
  ```

- If the file is missing, `TestMain` skips the package with
  "run integration/run-cinc-server-erlang.sh". CI therefore compiles and lints
  the package but never contacts AWS.
- The client uses `WithHTTPClient` with a transport whose `RootCAs` contains
  only the CA from `ca_cert_path`.
- `TestMain` waits for readiness before running tests: `GET /_status`
  returning 200, then an authenticated `GET /organizations/<org>` returning 200,
  polling for up to 20 minutes. On timeout it fails and points at
  `/var/log/cloud-init-output.log`, reachable through SSM.
- `Gaps` starts empty. The erlang server is the reference, so a failure is a
  client bug until shown otherwise. Entries are allowed only for server
  limitations (for example, a server-admin being unable to create orgs), and
  each states what was observed.

## Section 3: Terraform (`integration/terraform`)

### Providers and inputs

- `aws`, `tls`, `http`, `local`, pinned in `required_providers`;
  `.terraform.lock.hcl` committed. Local state only.
- Variables and defaults:

  | Variable | Default |
  |---|---|
  | `region` | `us-west-2` |
  | `instance_type` | `t3.xlarge` (4 vCPU, 16 GB) |
  | `cinc_server_version` | `15.10.125` |
  | `allowed_cidr` | caller's public IP /32, looked up from `https://checkip.amazonaws.com` |
  | `name_prefix` | `cinc-api-it` |

### Resources

- **Network:** its own VPC, one public subnet, internet gateway, route table.
  Works in accounts without a default VPC and destroys cleanly.
- **Security group:** inbound 443 from `allowed_cidr` only. No port 22.
- **Instance:** Ubuntu 22.04 AMI from Canonical's public SSM parameter
  (`/aws/service/canonical/ubuntu/server/22.04/stable/current/amd64/hvm/ebs-gp2/ami-id`);
  IMDSv2 required; encrypted 50 GB gp3 root volume; instance profile with
  `AmazonSSMManagedInstanceCore` for debugging; no key pair;
  `instance_initiated_shutdown_behavior = "terminate"`; tags include
  `cinc-api-integration = "true"`.
- **Elastic IP:** allocated before the instance so the certificate can name it.
- **TLS:** `tls_private_key` + `tls_self_signed_cert` for a throwaway CA;
  `tls_locally_signed_cert` for a server certificate with the Elastic IP as
  an IP SAN. The server certificate and key reach the instance in user-data;
  only the CA certificate is written locally. Anyone in the AWS account who
  can read the instance's user-data can see this throwaway TLS key.
- **Admin key:** `tls_private_key` (RSA 2048). Only the public key is in
  user-data.
- **Package pin:** the `http` data source reads
  `https://omnitruck.cinc.sh/stable/cinc-server/metadata?p=ubuntu&pv=22.04&m=x86_64&v=<version>`
  when you apply; the package URL and SHA-256 are passed into user-data.

### Bootstrap (cloud-init user-data)

1. `shutdown -h +240`, so a forgotten stack terminates after 4 hours.
2. Download the `cinc-server-core` package, verify its SHA-256, `dpkg -i`.
3. Write the server config: `api_fqdn` = the Elastic IP, nginx SSL certificate
   and key paths pointing at the provided files. The config file's exact path
   under `/etc/cinc-project/` is confirmed during implementation.
4. `cinc-server-ctl reconfigure`.
5. Create the admin user (random password, not kept) and the org, with the
   admin as a member; replace the admin's default key with the Terraform
   public key; `cinc-server-ctl grant-server-admin-permissions <admin>`.
6. Write `/var/lib/cinc-api-it/ready`. A failed step leaves its error in the
   cloud-init log.

### Outputs

`local_sensitive_file` writes `.out/admin.pem`, `.out/ca.pem` and
`.out/target.json` with mode 0600. `.gitignore` covers `.terraform/`,
`*.tfstate*` and `.out/`.

## Section 4: run script, CI, docs, delivery

### `integration/run-cinc-server-erlang.sh`

- `bash`, `set -euo pipefail`. Requires `terraform` and `go` only.
- Default: `terraform init` → `terraform apply -auto-approve` →
  `go test -count=1 -v ./cincservererlang`; a `trap` on EXIT runs
  `terraform destroy -auto-approve` whether the tests passed or failed.
- `KEEP=1` skips the destroy so tests can be re-run against the same stack.
- `./run-cinc-server-erlang.sh destroy` tears down a kept stack.
- Exits with the test result's exit code.

### CI

- The existing `integration` job (`go test -race ./...` in `integration/`)
  runs `suite` through `cincserverng`; `cincservererlang` compiles and skips.
- New steps in that job: `terraform fmt -check -recursive` and
  `terraform init -backend=false && terraform validate` in
  `integration/terraform`, using `hashicorp/setup-terraform` pinned by SHA.
- Dependabot: weekly `terraform` entry for `/integration/terraform`.

### Docs

- `integration/README.md`: prerequisites, what the stack creates, cost
  (about $0.17/hour for `t3.xlarge` plus the Elastic IP; a run takes about
  20–30 minutes), `KEEP`/`destroy`, debugging over SSM.
- `AGENTS.md` Testing section: the three packages; how to run the
  cinc-server-erlang suite; gap rules (every cinc-server-ng gap links an
  issue and is removed once the issue is fixed); any change to a request or
  response format is run against cinc-server-erlang before merge.

### Delivery (separate PRs, in order)

1. Restructure into `suite` + `cincserverng`, moving the existing tests with
   no behaviour change.
2. Expand CRUD coverage in `suite`, split by endpoint family, each PR adding
   its cinc-server-ng gaps and filing upstream issues.
3. Terraform stack, `cincservererlang`, run script, CI validation, Dependabot
   entry, docs.
4. First cinc-server-erlang run; each client bug found gets its own fix PR.

## Out of scope

- A GitHub Actions workflow for the erlang suite (can be added later with
  OIDC; this design keeps everything local).
- Remote Terraform state.
- High-availability or multi-node CINC Server topologies.
- Load or performance testing.
